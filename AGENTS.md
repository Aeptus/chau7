## Broker Coordination: before and after an edit

Other agents may be working in sibling worktrees.

Installed, trusted hooks deliver current-session actions, relevant peer
changes and changes to repository warning counts at prompt and tool boundaries.
Use `aethyme broker status --json` in your worktree to inspect the session on
demand. Add `--session <id>` from another checkout. Reuse its revision with
`--since-revision <token>` for changes only. Treat deferred checks as unknown.
Use `aethyme broker status --full --json` for exact session or lease-path
evidence. Check overlapping work before duplicating it. Overlaps with an
active session's explicit lease are advisory. Reconcile before merging and
resolve blockers and refusals.

1. `aethyme broker start --task "<task>"`, then work only in the worktree it
   reports and follow the working agreement it prints. Never edit another
   session's worktree.
   Before running repository tools or audits, check the session's preparation
   status and follow its `next_action` when dependencies are required:
   `aethyme broker submit prepare status --session <id> --json`. Preparation
   is explicit; do not assume a fresh worktree has installed dependencies.
   Builds, temp files, logs and checkouts go in its `scratch_dir`, never `/tmp`.
2. Commit early and small. Run `aethyme broker advance --session <id>` from a
   clean worktree and follow its next action. Add `--pr` after the first meaningful
   commit to open a draft. Use `aethyme broker push --session <id>` directly
   when publishing only the committed changes from a dirty worktree. Sync before
   resuming a reused session and validate the current merge candidate before merging.
   Never leave work only in the worktree. To build on another session's
   unmerged work, start with `--stack-on <id>`: the broker targets your PR at
   its branch and retargets it when that PR merges; never edit PR bases yourself.
3. When done: `aethyme broker submit --session <id>` runs the gates and lands
   nothing. Merge the PR on GitHub, then `aethyme broker finish --session <id>`
   (it refuses while commits are unpushed).

This repository's `push_session_branches` policy authorizes pushing your own
session branch and opening a draft PR; nothing else. Other remote or shared Git
and GitHub writes go through `aethyme broker advanced git` and
`aethyme broker advanced gh`. If `.aethyme/broker-action-required.md` appears,
read it first. Leases, gates, advisories and recovery: `references/broker.md`.

Standing authorizations (`[authorization]`), for every session without asking
again: `aethyme broker submit prepare --session <id>` in your own worktree as
soon as the broker reports it required (the declared frozen, pinned installs; no
dependency or lockfile change); creating, using and dropping local test
databases and environments named for the session (`$AETHYME_TEST_DB_SUFFIX` or
the script's own scratch name), broker-leased (`aethyme env`) or made by the
repository's declared test or scratch commands, then dropped (never shared,
staging or production data). Nothing else is implied.

## Finding code

For "where is X" questions, try `aethyme explore --request "<question>" --format brief`
first: one call prints a ranked summary and the top verified source spans. It
is a navigation aid, not an answer. Verify the spans before relying on them.
Read code in a session worktree, not the main checkout: the main checkout may
be behind the default branch, and Explore flags answers from a stale tree.
