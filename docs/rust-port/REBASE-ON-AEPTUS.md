# Chau7 Next: rebase on Aeptus/chau7

Chau7 Next was ported on `schiste/chau7`, a copy of the repository taken in
April 2026. The real repository is `Aeptus/chau7`, whose `main` is about
2,400 commits ahead with unrelated history. Branch `feat/chau7-next-aeptus`
starts from `aeptus/main`, imports `apps/chau7-next`, `docs/rust-port`,
`spikes/gpui-tabbar`, the two `chau7-next` workflows and
`docs/remote-control/VIEWER-PROTOCOL.md` unchanged, then re-applies the old
branch's changes outside `apps/chau7-next` by intent (the files changed too
much for a textual rebase). This note records what moved, what changed in the
coexistence rules, and where the Swift app grew since April, to scope the
follow-up inventory delta (not done here).

## 1. Re-applied changes outside `apps/chau7-next`

| Area | April change | On the Aeptus code |
|---|---|---|
| `chau7_terminal` crate type | `rlib` added | Same. The crate is now a member of the `apps/chau7-macos/rust` workspace (with `chau7_parse`, `chau7_md`, `chau7_optim`) and pins Rust 1.96.0; Chau7 Next uses it as a path dependency with its own toolchain |
| `chau7_terminal/build.rs` | `CHAU7_TERMINAL_SKIP_CBINDGEN`, explicit `rerun-if-changed` | Same. The regenerated header is byte-identical to Aeptus's (checked by deleting it and rebuilding) |
| `new_with_env_in_dir`, `new_with_args_env_in_dir` | Added args and cwd to the constructor | Aeptus added `new_with_launch(args, cwd)` for the Swift app; the two Rust names are now thin wrappers over it |
| `src/rust_api.rs` | Rust-only accessors | Rebuilt on the new cell layout: `GridCopy` keeps the first `char` per cell plus `width`, `continuation` and a side table of multi-character grapheme clusters; `underline` comes from `CellData::underline_style` (it was the `_pad` byte); `echo_fd` and `wait_input_writable` use the new lock-free duplicated fd (`Chau7Terminal::echo_fd`); `is_alt_screen` reuses `is_alternate_screen_active` |
| Image anchors and arguments | `anchor_row`/`anchor_col` moved to where the image arrived | Not done that way: `anchor_*` keep their C API meaning (the cursor after the whole chunk, as Swift sees it). The arrival point goes into new Rust-only fields `arrival_row`, `arrival_col`, `history_size`; `args` keeps the iTerm2 arguments (with their `File=` prefix). Parsing is split at each image only to record the arrival point, the parser state is the same |
| Unix guards | `master_fd`, `tcgetattr`, `Drop` | Aeptus now has a shared `poll()` reader pool, `TIOCSWINSZ` resizes and `killpg(SIGWINCH)` nudges, all Unix-only. They are behind `cfg(unix)` helpers; other targets (Chau7 Next on Windows CI) read the PTY on one thread per terminal with the same channel messages |
| `chau7_optim` | Strip `CHAU7_CTO_BIN_DIR` folders from `PATH` | Re-applied on the new `strip_cto_wrapper_dir_from_path` (trailing-slash tolerant, `dirs::home_dir` fallback). Aeptus also added the `CHAU7_CTO_OPTIM_ACTIVE` sentinel |
| `services/chau7-remote` | Viewer frames 0x60 to 0x64, viewer hub, `chau7-remote viewer` | Same frames and hub on the new agent (module path `github.com/chau7/chau7-remote`, `coder/websocket`, `ctx` on every handler). Viewer frames from the relay are accepted only in cleartext. The end-to-end test now provisions relay credentials from a keyring (`CHAU7_E2E_RELAY_AUTH_KEYS`) and passed against `wrangler dev`. `CHAU7_REMOTE_STATE` handling needed no change (Aeptus supports it) |
| `services/chau7-relay` | `/view/<code>`, `share:<code>` registry, `src/viewer.js` | Rewritten for the Hibernatable WebSockets API: viewer sockets are tagged `viewer`, their routing state lives in socket attachments and the share code in storage, so routing survives eviction. Viewers need no relay credential (the keyring only admits Macs and phones); a misconfigured relay still refuses them. Per-IP attempt limits use the new in-memory token buckets (`viewattempt`, one session object per IP). Unit tests plus an integration test through the real Worker |
| Docs | `SPEC-Remote-Control.md`, root `README.md`, `AGENTS.md`, `.gitignore` | The spec was removed upstream; the frame list now lives in `services/chau7-remote/docs/PROTOCOL.md`, which lists 0x60 to 0x64. The root `AGENTS.md` and `CLAUDE.md` are generated by Aethyme ("do not edit"), so the Chau7 Next agent notes moved to `apps/chau7-next/README.md`. `.gitignore` already covered `apps/chau7-next/target/` |

## 2. Chau7 Next changes needed by the new base

- Remote grid snapshots: the Swift app and the iOS app now use the "CHG2"
  layout (20-byte cells with grapheme clusters). `remote::grid_snapshot` and
  `remote/snapshot.rs` encode CHG2; CHG1 would be rejected by the phone.
- Inline images use the arrival fields above.
- Localization: the four Swift tables (en, fr, ar, he) were copied again. The
  Swift app also ships Spanish (`es.lproj`) now; Chau7 Next does not yet.
- `bundle-macos.sh` adds the target to the pinned toolchain of the helper
  workspace before building `chau7-optim` and `chau7-md`. Paths of the Go
  services, the proxy and the icon did not move; the CI workflow needed no
  change.

## 3. Coexistence rules changed

Checked against the current Swift sources (`.chau7`, `Application Support`,
`com.chau7`, sockets, ports, `chau7://`, `CHAU7_*`). Unchanged: bundle id
`com.chau7.app`, MCP server name `chau7` and `~/.chau7/mcp.sock`, proxy ports
18080 / 18081, URL scheme `chau7`, Application Support folder `Chau7`.
New, and handled:

| Swift app now | Risk for Chau7 Next | Done |
|---|---|---|
| Relay credentials in `CHAU7_REMOTE_CREDENTIALS`, default beside the state file | An inherited or default value could reach the Swift app's credentials | The agent always gets `~/.chau7-next/remote/credentials.json` |
| Agent and proxy exit when `CHAU7_PARENT_PID` goes away | A stale inherited PID | Both get Chau7 Next's PID |
| Proxy reads global prompt rules from `CHAU7_INJECTION_RULES`, default `~/.chau7/prompt-rules.json` | Chau7 Next's proxy would apply the Swift app's rules | Passed `~/.chau7-next/prompt-rules.json` |
| Shell wrappers export `HISTFILE=~/.chau7/history/<tab>.*_history` | Shells of a Chau7 Next started from a Chau7 tab would write the Swift app's history | Dropped at startup when it points there |
| Codex proxy wrapper folder (`$TMPDIR/smartoverlay/bin`) put first on `PATH`; `BASH_ENV` and fish `XDG_CONFIG_HOME` in that folder | Codex and shells routed through the Swift app | Wrapper dropped from `PATH`, `BASH_ENV` dropped, `XDG_CONFIG_HOME` restored from `CHAU7_USER_XDG_CONFIG_HOME` |
| `ANTHROPIC_CUSTOM_HEADERS` with `X-Chau7-Session/Tab/Project` lines, `OPENAI_BASE_URL` with a `/_chau7/project/...` path | Swift attribution on Chau7 Next's API calls | Headers restored from `CHAU7_ANTHROPIC_CUSTOM_HEADERS_BASE` (or the `X-Chau7-` lines removed); the local-proxy URL is dropped as before |
| Claude Code hooks and status line, Codex notify hook (`~/.chau7/bin/chau7-claude-hook`, `chau7-claude-statusline`, `chau7-codex-notify`, entries in `~/.claude/settings.json` and `~/.codex/config.toml`), usage files in `~/.chau7/usage/`, plans in `~/.chau7/sessions/`, `~/.chau7/cto_state.json` | Chau7 Next must not install or edit them | Not touched. These hooks are global, so they also run for AI CLIs started in Chau7 Next tabs and write to the Swift app's files: a known side effect of the Swift app, listed in `DUAL-SHIP.md` |
| Skill installs (`.chau7-skill.json`, `.chau7-backups`, `~/.chau7/backups/skills`) | Shared AI CLI skill folders | Not ported; must use its own markers when it is |

The isolation test (`no_swift_app_paths_outside_data_root`) now also rejects
`smartoverlay`, `.chau7-skill`, `.chau7-backups`, the three helper names and
`credentials.json` outside `data_root.rs`. Details in `DUAL-SHIP.md` and the
inventory README.

## 4. Not carried over, or open

- Remote control from Chau7 Next needs relay credentials now (the relay only
  admits provisioned devices, `services/chau7-remote/docs/CREDENTIALS.md`).
  The agent gets its own credentials path, but Chau7 Next has no UI to run
  `chau7-remote identity` and `provision`; until then its remote control
  cannot connect to a production relay.
- The Swift app's remote grid is now delta-based on the Mac side
  (`RemoteGridSnapshotCache`, generation counters); Chau7 Next still sends a
  full snapshot each time (same wire format).
- Grapheme clusters reach `GridCopy`, but the GPUI painter still draws only
  the first `char` of each cell, as in April.
- The `CHAU7_CTO_OPTIM_ACTIVE` sentinel check in the CTO wrappers, Spanish,
  the new hooks, skills, usage, dashboard and the rest of section 5 are
  inventory delta.
- Two Linux-only failures exist on `aeptus/main` itself and remain: the
  `chau7_terminal` test `launch_args_and_cwd_reach_the_child` (uses
  `/private/tmp`) and two agent tests that need macOS `ioreg` (they pass with
  a fake `ioreg` on `PATH`).
