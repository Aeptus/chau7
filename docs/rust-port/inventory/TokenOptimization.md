# TokenOptimization

Swift: `apps/chau7-macos/Sources/Chau7/TokenOptimization/` (4 files, 1504 lines), plus `Chau7Core/TokenOptimization.swift` (621 lines), `Settings/Views/TokenOptimizationSettingsView.swift`, CTO hooks in `Terminal/Session/TerminalSessionModel.swift`, `Overlay/OverlayTabsModel.swift`, `Overlay/OverlayTabsModel+TabSwitchOptimization.swift`, `Overlay/TabHoverCard.swift`
Swift tests: `TokenOptimization/TokenOptimizationTests` (`TokenOptimizationCoreTests` runs under `swift test`; `TokenOptimizationIntegrationTests` is app target only)
Wave: 3
Depends on: Terminal (shell environment, first prompt, input lines), AI (AI CLI detection drives "AI only" mode), Overlay (per-tab override, hover card), Settings, MCP (`tab_set_cto` tool). Helper binaries: `chau7-optim` (Rust, `apps/chau7-macos/rust/chau7_optim`, forked from RTK) and `chau7-md` (Rust, `apps/chau7-macos/rust/chau7_md`).

"CTO" (Command Token Optimization) makes common CLI commands print compact output when an AI coding tool is reading the terminal, to save tokens. Chau7 puts small wrapper scripts for `git`, `ls`, `cat`, `grep`, `npm`... first on the shell's PATH. When the tab is "optimized" (a per-tab flag file exists), the wrapper runs `chau7-optim <subcommand>` which rewrites verbose output into a summary; otherwise the wrapper execs the real binary at almost no cost. Savings are tracked by the optimizer and shown in settings.

## Notes

**Paths are hardcoded in shell code.** The generated wrappers contain literal `$HOME/.chau7/cto_bin`, `$HOME/.chau7/cto_active/$CHAU7_CTO_SESSION` and `$HOME/.chau7/bin/chau7-optim` / `chau7-md`, and `chau7-optim` strips only `$HOME/.chau7/cto_bin` from PATH before running real commands (`rust/chau7_optim/src/main.rs`). Chau7 Next must generate wrappers with its own data root (`~/.chau7-next/cto_bin`, `cto_active`, `cto_data`, `bin`) and must make the optimizer strip that folder too (pass the folder in an env var, or patch `main.rs`), otherwise the optimizer finds the Next wrapper for `git`/`ls`, which calls the optimizer again: infinite recursion. All of these are DataRoot paths; add them to `data_root.rs`.

**Shared optimizer database.** `chau7-optim` tracks savings in `RTK_DB_PATH`, else its config file, else `dirs::data_local_dir()/rtk/history.db` (`~/Library/Application Support/rtk/history.db`). Neither app sets `RTK_DB_PATH`, so both would share one savings history. Chau7 Next should set `RTK_DB_PATH` into its own data root in the shell env.

**Decision table** (`shouldBeActive`): mode Off -> off; override forceOff -> off; forceOn -> on; All Commands + default -> on; AI Only + default -> on only when an AI CLI is detected in the tab; Manual + default -> off. Reasons logged: `off, allTabsDefault, aiOnlyWithAI, aiOnlyWithoutAI, manualDefault, forceOn, forceOff, skippedDueToDeferred, unchanged`.

**Rewrite map** (`ctoRewriteMap`, command -> optimizer subcommand): cat->read, sed->read, ls, find, tree, grep, rg, git, diff, cargo, curl, docker, kubectl, gh, pnpm, wget, npm, npx, vitest, prisma, tsc, next, lint, prettier, format, playwright, ruff, pytest, pip, go, golangci-lint, swift, python, python3->python. Exec-only: head, tail, wc. Pipe filters: grep, rg, diff, sed.

**Wrapper contract.** Bash scripts (`#!/bin/bash`). Fast path when `CHAU7_CTO_SESSION` is empty or its flag file is missing: one `exec` of the hardcoded binary. Optimizer exit codes: 0 or any code other than 2/3 = done (exit with it), 2 = clap parse failure (fall through), 3 = intentional skip (fall through). Command log line: `<unix seconds>|<session>|<command>|<exit code>|<optimized|skipped|fallthrough>` appended to `$CHAU7_CTO_LOG`. Wrappers are regenerated on every setup (app start with mode on, mode change, Reinstall). Unix only; on Windows this feature needs a different design.

**Gain JSON** (`chau7-optim gain --daily --format json`): `{"summary":{total_commands, total_input, total_output, total_saved, avg_savings_pct, total_time_ms, avg_time_ms}, "daily":[{date "yyyy-MM-dd", commands, input_tokens, output_tokens, saved_tokens, savings_pct}]}`.

**Runtime health score** (`CTORuntimeSnapshot.assessment`): start at 100; -30 low change rate (<30% while not stable), -30 deferred skip rate >35% (with >= 5 deferred), -20 deferred flush rate <80% (with >= 5 deferred), -15 no decision for 300 s with active sessions while not stable, -20 mode Off with tracked sessions, -10 no recalculation after 60 s uptime with tracked sessions. >= 85 healthy, >= 65 warning, else critical. Stable = at least 10 recalcs, more than half unchanged, no active session.

**Settings keys** (UserDefaults, also in settings export JSON): `cto.mode` (default `off`, legacy `rtk.mode`), `tabs.display.allowCTOToggle` (true), `feature.ctoEnabled` (false), `feature.ctoPrefix` (""), `feature.ctoTabOverrides` (dictionary tab id -> bool). Per-tab mode override is stored in the tab restore state as `tokenOptOverride` (`forceOn` / `forceOff`, absent = default).

**Port options.** `chau7_optim` and `chau7_md` are already Rust crates in this repo; Chau7 Next can ship them as separate binaries (simplest, keeps the wrapper contract) or link them as libraries later.

**TOK-022 n/a:** Chau7 Next starts with its own data root and never had RTK folders or keys.

**Not set by the app:** `CHAU7_CTO_EXCLUDE` is read by wrappers but Chau7 never sets it (users can export it in their shell).
