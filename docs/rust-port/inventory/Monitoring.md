## Notes

- MON-001/002/003: `ai::hub` follows `~/.chau7/claude-events.jsonl` every 250 ms, read only, alongside the owned Next Claude helper queue (Next never creates or rotates the Swift queue). Timestamps without fractional seconds are accepted too. Session state per hook event: user prompt -> active, tool start or tool complete -> responding, permission request -> waiting permission, response complete -> waiting input, session end -> closed. The "waiting for input" fallback fires 0.75 s after a response completes.
- MON-004: the transcript parser is ported (`claude_code::latest_messages`); MCP, remote and the debug views call it once ported.
- MON-006: the history idle monitor is `history::monitor` (settings in Settings > Logs & History: `[next] monitor_history_logs`, `history_idle_seconds` (5), `history_stale_seconds` (180), history paths); `ai::hub` publishes its "idle" and "finished" notices on the AI event feed with the session's directory. The histories are `~/.claude/history.jsonl` and `~/.codex/history.jsonl`, read only.
- MON-007 to 010: the detector's config is the one Settings > Notifications edits (`[next] notification_shell_events`, Swift's `ShellEventConfig` as JSON: watched exit codes, output patterns, long-running threshold, directory and branch switches), applied to open sessions when settings change. Shell events reach the notification engine only through the AI event feed. Chau7 Next reports `command_finished` once per command (Swift also reports it when an AI run ends, which doubles it). Long-running tiers are checked every second instead of every 5 s.
- MON-011: listening ports come from `netstat -anv -p tcp` on macOS and `/proc/net/tcp` plus `/proc/<pid>/fd` on Linux (`platform::process::listening_port`). A server found again on the same port and pid keeps its name (Swift renames it "Node Server" once the command hint is used up).
- MON-012: CPU and memory come from libproc / `/proc` (two samples for CPU) instead of `ps`; the poll interval follows `MonitoringSchedule.nextPollInterval`.
- MON-013: Swift counts panes whose session status is running, waiting for input or stuck (from shell integration); Chau7 Next counts direct children of each pane's shell (`proc_listchildpids` on macOS, `/proc` on Linux). Same user-visible result for the close confirmation.
- MON-014/015: git runs with `GIT_TERMINAL_PROMPT=0` and a 5 s kill timeout (`monitoring::git::run_git`). The change set is the symmetric difference of the two dirty sets, so files committed or reverted by the command count too. Conflicts are checked when a tab reports changed files; closed tabs are dropped. `FileConflict.repoRoot` is always empty, as in Swift.
- MON-017/024: FileMonitor uses notify with kqueue on macOS. Actual editor/external-change consumers hold watcher lifetime; parent recovery handles missing hierarchies, deletion/recreation and atomic replacement. Generation guards prevent resurrection after stop. Root adds deterministic rearm acknowledgement and replacement-gap catch-up; focused atomic-replacement tests and full-suite validation cover the real consumer.
- Overlapping rows in other inventories (update both when porting): MON-011 with TRM-047 and OVL-010.

## Remaining current-source facets
- MON-019: shared Claude metadata/history caches are bounded to 256/4 entries and scoped by home, fingerprint size/modification/creation/inode, retry negative results after two seconds, revalidate transcript deletion, validate event path identity, and reconcile exact current/legacy project-folder encodings. The real hook worker enriches missing CWD and validates transcript ownership off UI before adopting a unique native terminal identity. Codex exact IDs search every known day folder; discovery exposes separate reference and 3/14-day windows, and the metadata cache is bounded to 256 per home. The existing worker resolves the latest 64 history identities with a two-second missing-rollout retry; UI captures consume immutable cached candidates. Original notice timestamps survive delayed projection. Runtime rollout/DB feedback discovery remains in MON-018. Validation: eight isolated Claude resolver tests, six Codex resolver tests, three hub tests; the combined source passed 2,250 core and 358 app tests and strict release workspace all-target Clippy/fmt. Actual provider/native-window capture remains unverified.
- MON-020 implements one subscribed 1.5-second native snapshot worker, immediate refresh and two coalesced 0.2/0.6-second launch refreshes. There is no scan or registered timer with zero subscribers; weak terminal subscriptions are dropped on exit/close, and quit cancels owned fallback commands. A deterministic breadth-first resolver handles interpreter/script paths and cycles. Positive observations repair canonical provider metadata without discarding same-provider native resume identity; the current Swift running predicate also retains a non-restored shell-command fallback when a native match is absent. Numeric capture timing is exported through the profiler. Validation: five resolver tests, two identity tests, four real native/scheduler/idle-worker tests; release suites passed 2,215 core and 348 app tests, strict workspace all-target Clippy and formatting passed. Actual provider/window interaction remains unverified. Windows uses native process names; unavailable interpreter arguments remain unknown, and Windows runtime acceptance awaits CI/hand testing.
- MON-021 stays partial: robust single-file watch recovery is done in MON-024, but the deduplicated shared FileSystemWatchRegistry and LogFileCompactor remain separate unimplemented facets.
- MON-022 implements the current durable outbox adapter, not a filesystem inbox. It uses current `broker advanced` commands, adapter `chau7-next`, `chau7-next://tab/<UUID>?session=<native-id>` targets and worker/generation-fenced acknowledgements. Polling starts after 15 seconds and repeats after 30 seconds without overlap; incomplete captures back off for 30 seconds and incompatible deployments for 10 minutes. Command stdout/stderr together are bounded to 4 MiB and 15 seconds, including descendant-held pipes, and only owned commands are terminated. Filesystem resolution runs off the UI thread; target identity, effective prompt/status, pending typed fragment/queued prefill and cached repository root are rechecked atomically before terminal acceptance. A target receives at most one accepted prompt per cycle. Validation uses fake executables and isolated files; no live broker subscription/claim or native delivery acceptance has been exercised.
- MON-023: final feedback projection verifies provider, native identity, directory component boundaries, exit/input timestamp and a unique real pane. A mismatched explicit stamp attempts one exact alternate owner, then suppresses repeat diagnostics and reports a numeric suppression summary every 60 seconds; quarantine is bounded to 512 sources and cleared after valid ownership. Original raw spine events remain durable, while terminal status and notifications receive only the reconciled owner. Concurrent splits cannot steal another native session approval; exact completion after the AI process ends remains valid. Claude adoption requires shared resolver transcript ownership and unique live CWD match. Regression tests cover ambiguous owners, guarded identity adoption, quarantine cadence/caps and invalid clocks; source validation is the same combined suite above. Real-provider/native UI acceptance remains separate.
- Source completion of MON-018/019/023/024 does not imply native real-provider capture or all of the distinct shared-monitor services above.
