# AI

Swift: `apps/chau7-macos/Sources/Chau7/AI/` (5 files, 962 lines)
Swift tests: `AI/AITerminalLogSessionTests.swift`, `AI/LLMProviderTests.swift`, `AI/AccessibilityTests.swift` (contains `AIEventParserTests`), `Terminal/CommandDetectionTests.swift`, `Terminal/AIDetectionStateTests.swift`, `Monitoring/AIResumeParserTests.swift`, `Monitoring/AIEventParserTests.swift`
Wave: 2
Depends on: Terminal (shell integration, output stream), Settings, Overlay (tab chrome); Monitoring for hook events

Recognizes AI coding CLIs (Claude Code, Codex, Gemini, ChatGPT, Copilot, Aider, Cursor, Windsurf, Cline, Cody, Amazon Q, Devin, ...) running in a tab, brands the tab with the tool's name, logo and color, keeps a PTY log of each AI session and writes start/finish events to the AI events log. It also holds the "bring your own AI" layer: LLM provider settings with API keys in the Keychain, an HTTP client for OpenAI, Anthropic, Ollama and custom endpoints, and the "Explain This Error" feature.

Detection and resume logic lives in `Chau7Core` (`CommandDetection`, `AIToolRegistry`, `AIDetectionState`, `AIResumeParser`, `LLMProvider`); rows below point there when that is where the behavior is.

## Notes

- AIX-001/003: the typed command line is detected by `ShellSession` (PATH aware, wrappers, custom rules) before the output banner; the prompt return keeps the tool for the 5 s re-detect window and restored tabs keep it (`AiDetectionState`).
- AIX-009/010: under DUAL-SHIP.md section 3, Chau7 Next writes the PTY logs to `DataRoot::ai_logs_dir()` (`<tool>-pty.log`) and its start/finish lines to `DataRoot::ai_events_log()`, never to the Swift paths. Swift's per-tool log path settings (`codexTerminalPath`, `claudeTerminalPath`) are not settings in Chau7 Next. The cap comes from `CHAU7_PTY_LOG_MAX_BYTES` (`CHAU7_NEXT_PTY_LOG_MAX_BYTES` first). One writer thread writes every session's log in order.
- AIX-011: `ai::hub` follows `~/.ai-events.log` (read only: never created, truncated or rotated) and Chau7 Next's own events log; lines with source `terminal_session` only feed the timeline, as in Swift. Every event goes through `ai::events_out::publish`, which the notification engine subscribes to (`events_out::subscribe`). Events raised by a tab carry the tab in `tab_id` (`events_out::tab_uuid` / `tab_from_uuid`). The Swift `logPath` setting and `CHAU7_EVENTS_LOG` are not read.
- AIX-012: unlike Swift, the endpoint, model and max tokens are saved (`[next] llm_provider`, `llm_endpoint`, `llm_model`, `llm_max_tokens`); empty means the provider default. Changing the provider clears them.
- AIX-013: keys are stored with `platform::secrets` as `com.chau7.next.llm.<provider>.apikey` (account `apikey`). Importing the Swift app's keys (DUAL-SHIP.md) is not offered.
- AIX-014: requests go through `curl` (on macOS, Linux and Windows 10+), with the request on curl's standard input so the key is not visible in the process list; 30 s timeout. Transport errors show curl's message.
- AIX-015/016: "Explain This Error" is wired as designed: when a command fails in a tab (OSC 133 exit code) and `[next] error_explain_enabled` is on, the tab shows "Exit N - Explain This Error" at the bottom right; the answer panel has the confidence badge, details and fixes (Apply types the command at the prompt without running it; dangerous fixes are copied). A later successful command removes an unused offer.
- Error explanation JSON schema: `{"summary","details","confidence":"high|medium|low","fixes":[{"description","command","risk":"safe|moderate|dangerous"}]}`. Default models: `gpt-4o`, `claude-sonnet-4-20250514`, `llama3.2`.
- Overlapping rows in other inventories (update both when porting): AIX-001/002/003 with TRM-041, COR-001, COR-005; AIX-008 with OVL-114, COR-004; AIX-012/013/017 with SET-104, SET-105, UTL-003.
